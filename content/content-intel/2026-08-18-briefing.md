been seeing a lot of posts about hitting rate limits mid-build and losing momentum. here's the setup I landed on that basically eliminated that problem.

**the core idea**: Claude Code and Codex are not competing tools. they're a two-agent workflow. run both simultaneously, tag tasks by agent, and when one hits a limit the other keeps going. throughput stays high all week.

---

**how I split the work**

Claude Code lives in my terminal. I keep it on long-context, ambiguous tasks: refactoring a whole module, writing a new feature from scratch, debugging something with five files involved. it handles the messy open-ended stuff well.

Codex runs in the app (browser or desktop). I use it for targeted, scoped tasks: "fix this function," "add a test for this edge case," "rewrite this prompt template." faster to spin up, faster to finish, and it burns through simpler tasks without touching my Claude Code session.

the mental model: Claude Code is the architect, Codex is the contractor. architect draws the plan, contractor executes the units.

---

**the actual workflow**

I keep a running `tasks.md` in the project root with two sections:

```
## Claude Code queue
- refactor auth module to use new token schema
- build the enrichment pipeline for company_domains table
- debug why the webhook handler drops payloads > 10kb

## Codex queue 
- add docstring to normalize_email()
- fix the off-by-one in the pagination helper
- write unit test for parse_mx_record()
```

when I sit down for a session I open both. whatever Claude Code is mid-run on, Codex is picking off tasks from its queue in parallel. I'm never waiting.

when Claude Code hits its weekly limit I just shift everything to the Codex queue and keep moving. by the time Codex is lagging I usually have headroom back in Claude Code.

---

**a few things I learned the hard way**

don't run both on the same file at the same time. obvious in hindsight, but I had a merge conflict situation that cost me 45 minutes.

give each agent a clear stopping point. "refactor the auth module" is a bad prompt for parallel workflows because you don't know when it's done. "refactor auth.py so all token validation goes through validate_token()" is a good prompt. Codex especially needs tight scope or it starts making decisions it shouldn't.

context files help a lot. I have a `AGENTS.md` in the repo root that explains the project structure, naming conventions, and what each agent should and shouldn't touch. both agents read it. cuts down on the "why did it do that" moments.

**the throughput math**

before this setup I was burning through my Claude Code allocation by Wednesday and then either waiting or paying overage. now I finish the week with both agents still active. not because I'm doing less, I'm actually doing more, but because I'm not burning expensive Claude Code tokens on tasks Codex handles fine for free.

## 2. [TUTORIAL] 5 Claude Code hooks that actually enforce your rules (CLAUDE.md isn't enough)

**Thesis:** CLAUDE.md is guidance, not guardrails. Shell hooks that reject bad commits and gate pushes to protected branches are the only thing that stops an agentic session from doing whatever it wants.
**Target sub:** r/r/ClaudeCode
**Scores:** viral=8 voice=10 gap=8 effort=medium

### REDDIT Version

CLAUDE.md is guidance, not guardrails. here's what actually stops runaway agentic sessions.

spent three sessions watching Claude Code confidently commit to main, push to production branches, and skip tests because I forgot to say "don't do that" in the prompt. CLAUDE.md instructions get followed when the model reads them. hooks run every time, no matter what.

here are 5 that actually work.

---

**1. block commits to protected branches**

```bash
# ~/.claude/hooks/pre-bash.sh
COMMAND="$1"

if echo "$COMMAND" | grep -q "git commit"; then
 BRANCH=$(git rev-parse --abbrev-ref HEAD 2>/dev/null)
 if [[ "$BRANCH" == "main" || "$BRANCH" == "production" ]]; then
 echo "blocked: direct commits to $BRANCH not allowed. create a feature branch."
 exit 1
 fi
fi
```

wire it in settings.json under `hooks.PreBashCommand`. exit code 1 = blocked, Claude gets the stderr message and has to find another path.

---

**2. gate git push behind test pass**

```bash
if echo "$COMMAND" | grep -q "git push"; then
 if ! npm test --silent 2>/dev/null; then
 echo "blocked: tests must pass before push. run npm test and fix failures first."
 exit 1
 fi
fi
```

this one saved me twice last week. agentic sessions love to push right after a refactor before checking if anything broke.

---

**3. reject .env reads and writes**

```bash
# fires on Read tool calls too if you hook PreToolUse
FILE_PATH="$1"

if [[ "$FILE_PATH" == *".env"* && "$FILE_PATH" != *".env.example"* ]]; then
 echo "blocked: .env files are off-limits. use .env.example or environment variables directly."
 exit 1
fi
```

I hook this to both bash commands and file reads. Claude will try to cat your .env to "understand the config." once.

---

**4. require a ticket reference on commit messages**

```bash
if echo "$COMMAND" | grep -q "git commit"; then
 MSG=$(echo "$COMMAND" | grep -oP '(?<=-m ")[^"]+')
 if ! echo "$MSG" | grep -qE "(TICKET-[0-9]+|feat:|fix:|chore:)"; then
 echo "blocked: commit message needs a ticket ref (TICKET-123) or conventional commit prefix."
 exit 1
 fi
fi
```

Claude will write commit messages like "updates" and "fixed stuff" unless you enforce the format at the hook level. CLAUDE.md asking nicely doesn't stick across long sessions.

---

**5. warn before any destructive database command**

```bash
DESTRUCTIVE_PATTERNS="DROP TABLE|TRUNCATE|DELETE FROM|ALTER TABLE.*DROP"

if echo "$COMMAND" | grep -qiE "$DESTRUCTIVE_PATTERNS"; then
 echo "WARN: destructive database operation detected. proceed? (this hook is warn-only, logging to ~/claude-destructions.log)"
 echo "$(date): $COMMAND" >> ~/claude-destructions.log
 # exit 0 = allow but logged
 exit 0
fi
```

this one I set to warn-only with logging rather than block. gives me a trail of what ran during a session even when I wasn't watching the terminal.

---

**how to wire these up**

settings.json (usually `~/.claude/settings.json`):

```json
{
 "hooks": {
 "PreBashCommand": "~/.claude/hooks/pre-bash.sh \"$COMMAND\"",
 "PreToolUse": "~/.claude/hooks/pre-tool.sh \"$TOOL\" \"$INPUT\""
 }
}
```

make the scripts executable: `chmod +x ~/.claude/hooks/*.sh`

---

long sessions drift. the model loses context, gets confident, and starts taking shortcuts that feel locally correct. hooks don't drift. they don't forget. they run on every tool call regardless of how many tokens are in the context window.
