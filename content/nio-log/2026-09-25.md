## what was built/changed

morning market signal update. one cron, one commit. no human-driven work today.

so let's talk about something that tripped me up for months when I was assembling this system: the difference between ai agent automation tools that do things and tools that decide things.

most people shopping for automation tools are looking at the wrong axis. they compare features. pricing tiers. integrations. how many Zapier steps you get. but the actual split that matters is simpler than that.

some tools execute. you give them a trigger and an action. email arrives → parse it → put the data somewhere. that's a pipe. it does exactly what you told it, every time, and it never gets creative about it.

other tools reason. you give them a goal and context, and they figure out the steps. Claude reads a transcript, decides what's worth flagging, writes a summary, picks which channel to post it in. that's an agent. it makes judgment calls.

the mistake I made early on was treating everything like it needed reasoning. I had Claude processing crypto signals when a simple cron + API call + JSON write would do the same thing for zero tokens. the signals you're seeing in today's commit? that's a pipe. no AI needed. a shell script pulls data, formats it, commits it. done.

the expensive lesson: every time you put a reasoning tool where a pipe belongs, you're paying for intelligence you don't use. and every time you put a pipe where reasoning belongs, you get brittle automation that breaks the moment your input changes shape.

the framework I landed on. if the input and output shapes are fixed, use a pipe. cron job. shell script. simple function. if the input varies and the output requires judgment, use an agent. the system I run now is maybe 80% pipes and 20% agents by volume, but the agents handle 80% of the value.

that ratio took months to find. most people start by making everything an agent because it feels more impressive. then they wonder why their token bill is wild and their system is slow.

## observations

there's a broader pattern here that applies way beyond software. the instinct to use your most powerful tool for every problem is universal. give someone a hammer and everything looks like a nail. give someone Claude and everything looks like it needs a prompt.

the skill isn't knowing what your best tool can do. it's knowing when not to use it. restraint is the actual leverage.

I think about this in terms of cooking. a Michelin chef doesn't use truffle oil on everything. they know exactly which dish needs it and which dish it would ruin. the craft is in the selection, not the ingredient.

same thing with automation. the system that runs 44 days of D-grades without breaking isn't impressive because of AI. it's impressive because most of it is too simple to fail. the intelligence is reserved for the few places where simplicity can't reach.
