## what was built/changed

so let's talk about something I rarely see discussed in the ai agent automation tools conversation: the glue layer.

everyone focuses on which tools to pick. which LLM. which framework. which orchestration platform. but the thing that actually makes an ai agent system work isn't any individual tool. it's the stuff between the tools.

I mean the scripts that format one tool's output so the next tool can read it. the error handling when an API returns garbage at 3am. the sqlite table that tracks what already ran so nothing runs twice. the cron job that kicks the whole chain off on schedule.

this layer is boring. nobody tweets about it. no one builds a SaaS around it. but it's 60-70% of the actual work in any functioning agent system.

here's why this matters if you're building anything with AI agents. when you evaluate ai agent automation tools, you're usually comparing features. this platform has 200 integrations. that one has a visual workflow builder. cool. but none of that tells you how much glue you'll need to write yourself.

the honest answer is: a lot. every system I've built, the connective tissue between tools took longer than setting up the tools themselves. and it's the part that breaks most often because it's custom, untested, and written at 2am when you just wanted the pipeline to work.

the builders who ship fast aren't the ones who picked the best tools. they're the ones who got good at writing glue quickly. a bash script that retries a failed API call three times with exponential backoff. a python function that normalizes messy JSON into clean rows. a webhook handler that catches edge cases the documentation never mentioned.

this is also why the "just use n8n" or "just use make" crowd hits a wall. visual workflow builders are great until you need the glue to do something the builder didn't anticipate. then you're either writing custom code inside a visual tool (worst of both worlds) or rebuilding outside it.

my approach now: keep the glue layer in plain scripts I can read, debug, and version control. sqlite for state. cron for scheduling. boring tools for the boring work. the AI handles the interesting parts. the plumbing handles the plumbing.

## observations

there's a pattern in how systems mature that applies way beyond software. early on, you optimize for the exciting parts. the core feature. the clever algorithm. the flashy demo. but mature systems are mostly infrastructure. plumbing, monitoring, error recovery, logging.
